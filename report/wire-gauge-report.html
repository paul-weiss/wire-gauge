Wire-Gauge

13th Gen Intel(R) Core(TM) i9-13980HX · linux 6.14.0-37-generic · pinned cores · 22 runs · 11,460,000 messages · 0 dropped · latest run 2026-08-31

Round-trip latency of 11 message transports under an identical, coordinated-omission-free workload: fixed-size 128B messages offered on a strict schedule, latency measured from intended send time, sends never gated on responses. Same harness, same machine, one echo process per run. Round one is this machine alone; round two, below the findings, is the network transports across a real wire.

The candidates

Shared memory

shm
The hand-rolled floor: a single-producer/single-consumer ring in the LMAX style over a file-backed shared mapping. The producer copies the payload and publishes an 8-byte sequence stamp with a release store; the consumer busy-spins on the stamp it expects. Flow control is backpressure, never overwrite, so a slow consumer surfaces as send lag instead of silent loss. No dependencies; everything else is measured against this. design: LMAX Disruptor
aeron-ipc
Aeron's same-host mode: publications write to shared-memory log buffers managed by its media driver (here embedded in the echo process, SHARED threading, spin idle — Aeron's published low-latency single-core profile). Identical API to aeron-udp, which is why Aeron is the hinge of this comparison. Via the rusteron FFI bindings over the vendored C client, statically linked. aeron.io docs · source · rusteron
iceoryx2
Rust-native zero-copy publish/subscribe from the Eclipse iceoryx lineage — decentralized shared-memory services with discovery, loaned samples, and safe overflow, no daemon. Run in its plain ipc flavor (no locking), exact-size payload loans, a 4,096-sample subscriber buffer, busy-poll receive. The strongest “don't hand-roll it” IPC candidate. docs · source

Kernel sockets

uds
A Unix domain stream socket — the practical same-host default everyone actually ships. Blocking std::net calls, fixed-size framing (read exactly one message), no framework anywhere in the path. unix(7)
tcp
TCP over loopback with TCP_NODELAY on both ends (Nagle would batch 128-byte sends and measure the algorithm, not the wire). The reference point for “just use TCP.” tcp(7)
udp
Connected UDP unicast over loopback, one datagram per message, deliberately unreliable: nothing retransmits and the harness counts drops instead of hiding them. The floor of the network axis — the delta to aeron-udp prices Aeron's reliability layer. udp(7)
aeron-udp
Aeron over UDP unicast: the media driver owns the sockets, adds sequencing, flow control, and gap detection, and hands messages to the client through shared memory. Classed with kernel sockets because the wire is UDP loopback; the machinery on top is what's being priced. transport docs

Brokered

nats
Core NATS: a lightweight broker doing fire-and-forget pub/sub — no persistence, no acknowledgments, a slow subscriber gets cut off. Driven through the official async client (async-nats) on a one-worker runtime, publish + flush per message so a send is on the wire before it returns. docs · async-nats
jetstream
NATS's persistence layer: both directions run through file-backed streams and delivery comes from an ordered pull consumer, so the number measured is publish → stored → delivered. Publisher-acknowledgment latency is deliberately not in this round. docs
redis
Redis Streams: append with XADD, consume with blocking XREAD, one single-threaded server in between. Run at its best case — no AOF, no snapshots — and every XADD is a full client–server round trip, so over-offered load shows up as send lag. docs
kafka
The durability and replay standard, as a single-node KRaft broker with one partition, driven by the official C client (librdkafka) at linger.ms=0 and acks=all. Enqueueing is asynchronous — delivery failures become counted drops, and saturation becomes queueing delay the schedule-honest harness can see. docs · librdkafka

Findings

Saturation is the story naive benchmarks miss. Kafka at 5k/s holds a respectable p50 of 114 µs — but at 50k/s it delivers every message, drops none, and the median rises to 241.4 ms: a 2,110× collapse. A single-partition, acks=all pipeline saturates below the offered rate, the backlog grows, and sojourn time becomes the latency. Only a load generator that measures from intended send time (coordinated-omission-free) sees this; send lag stays at 0.11 µs because enqueueing is asynchronous.

Aeron's reliability layer is approximately free at the median. aeron-udp (p50 5.03 µs) matches raw UDP sockets (6.43 µs) — the spinning media driver owns the sockets and hands messages to the client over shared memory, amortizing the per-message syscall path. The price appears in the tails instead: aeron-ipc p99 8.15 µs against iceoryx2's 0.94 µs.

The IPC ladder is tight and cheap. The hand-rolled SPSC ring holds 0.35 µs p50; Aeron IPC (0.53 µs) and iceoryx2 (0.81 µs) pay 1.5× and 2.3× respectively for service discovery, flow control, and not maintaining your own ring — all three are under a microsecond.

Single-box persistence costs far less than cluster folklore says. JetStream delivers persisted messages at 55.10 µs and Kafka at 114 µs — an order of magnitude under the millisecond bands hypothesized from public (clustered) numbers. One node, no replication, OS-async fsync: replication is the real cost, and a cross-host round can measure it. Redis Streams at 24.66 µs also beats NATS core (39.81 µs) here — one XADD round trip against two brokered hops plus an async client's runtime boundary.

What the wire changes

Across a real wire the raw transports converge. At 50k/s in one availability zone, TCP (86.40 µs), UDP (86.08 µs) and Aeron UDP (86.85 µs) sit within a few microseconds of each other at the median, and all of them run far under the idle ICMP round trip on the same pair: a virtual NIC coalesces interrupts when the link is quiet, and ping is always quiet. Aeron still owns the tail (p99 146 µs against TCP's 164 µs).

At low rate the busy-poll receiver is the difference. At 5k/s Aeron UDP holds 82.94 µs while TCP pays 262 µs: a socket that sleeps between messages pays a wakeup on every one, a spinning media driver does not. The same spread vanishes at 50k/s, where the socket never gets to sleep.

A synchronous client cannot exceed one message per round trip, and the wire sets the round trip. The Redis and NATS clients here confirm each message before sending the next (XADD reply; publish + flush). On loopback that cost 25 µs and was invisible. At a 461 µs wire it caps throughput near 2,169 msgs/s, so an offered 5k/s to Redis turned into 6.1 s of queue, and NATS at 50k/s into 517.5 ms. Kafka's pipelined producer and Aeron's driver never hit this wall. Round two's lower rates exist to measure these systems under the ceiling; the saturated rows stay in the table because they are the honest record of what a request-response client does when the wire gets long.

Crossing an availability zone adds about 961 µs and tightens nothing. Aeron UDP at 50k/s across zones: p50 1.0 ms, p99 1.0 ms, zero drops. TCP: p50 1.0 ms, p99 1.3 ms. Distance moves the whole distribution; it does not widen the fast transports' tails.
